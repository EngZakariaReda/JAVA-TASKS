SQL Queries – Solutions1. String ComparisonQuery:    SELECT *    FROM employees    WHERE first_name > 'ahmed'      AND first_name < 'ali';How does it work?In Oracle, text values can be compared using comparison operators suchas >, <, >=, and <=.The query returns employees whose FIRST_NAME is strictly greater than‘ahmed’ and strictly less than ‘ali’ according to the database’s activecharacter collation.By default, Oracle uses binary comparison semantics. This means thecomparison follows the character sort values, rather than understandingnames alphabetically in the way a person might. The result can beaffected by the session’s NLS_SORT and NLS_COMP settings if linguisticcomparison is enabled.For example, with a typical binary, case-sensitive comparison:-   ‘ahmed’ is not returned because > excludes an exact match.-   ‘ali’ is not returned because < excludes an exact match.-   A value such as ‘akram’ can fall between these two values because    its second character (‘k’) sorts after ‘h’ and before ‘l’.-   Uppercase and lowercase letters may sort differently. Do not assume    ‘Ahmed’ and ‘ahmed’ are equal.Important: This is a character-by-character comparison, not a check fornames that come between Ahmed and Ali according to human or dictionaryconventions. If you need case-insensitive or language-aware ordering,configure/use the appropriate Oracle linguistic collation.2. Understanding ROWNUMQuery 1:    SELECT *    FROM employees    WHERE ROWNUM = 1;This query works because Oracle assigns ROWNUM as rows are selected. Thefirst row selected receives ROWNUM = 1, so it satisfies the conditionand is returned.Query 2:    SELECT *    FROM employees    WHERE ROWNUM = 2;This query returns no rows.Why? The first candidate row selected is assigned ROWNUM = 1. It doesnot satisfy ROWNUM = 2, so it is rejected. Since no row has beenreturned yet, Oracle does not advance to ROWNUM = 2 for the nextcandidate row. Therefore, the condition can never be satisfied.Query 3:    SELECT *    FROM employees    WHERE ROWNUM = 3;This also returns no rows for the same reason. The first candidate rowgets ROWNUM = 1 and is rejected; Oracle cannot reach 3.The important rule: A condition such as ROWNUM <= 3 works because Oraclecan accept the first row (1), then the second (2), then the third (3).But ROWNUM = 2 or ROWNUM = 3 cannot skip the earlier row and reach thatnumber.How can you get the second row?Option A – Use an inline view:    SELECT *    FROM (        SELECT employees.*, ROWNUM AS rn        FROM employees        WHERE ROWNUM <= 2    )    WHERE rn = 2;This first selects up to two rows and assigns them row numbers. Theouter query then returns the row numbered 2.Option B – Use ROW_NUMBER() (recommended when you need a defined order):    SELECT *    FROM (        SELECT employees.*,               ROW_NUMBER() OVER (ORDER BY employee_id) AS rn        FROM employees    )    WHERE rn = 2;Replace employee_id with the column that defines the order you want.Without ORDER BY, the database is not required to return rows in aparticular order.To get the first three rows in a defined order:    SELECT *    FROM (        SELECT employees.*        FROM employees        ORDER BY employee_id    )    WHERE ROWNUM <= 3;Summary1.  String comparisons use the database’s active collation. By default,    Oracle uses binary, case-sensitive comparison.2.  ROWNUM is assigned as rows are selected.3.  ROWNUM = 1 works because the first selected row gets number 1.4.  ROWNUM = 2 and ROWNUM = 3 do not work on their own because the first    candidate row is rejected before Oracle can assign a later number.5.  Use ROWNUM <= n for the first n rows, or ROW_NUMBER() in a subquery    when you need a particular row in a defined order.
